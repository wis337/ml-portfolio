# Fraud detection: обнаружение мошеннических транзакций

Модель на LightGBM, которая отмечает подозрительные транзакции по банковским картам, и FastAPI-сервис, который отдаёт решение по запросу. Порог принятия решения подобран по стоимости ошибок, а не взят по умолчанию.

## Данные

[Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) (ULB, Kaggle): ~285 тыс. транзакций, из них мошеннических 0,17%. Признаки `V1`-`V28` анонимизированы (результат PCA), плюс `Time` и `Amount`.

Файл `creditcard.csv` в репозиторий не входит (~150 МБ). Скачай его по ссылке и положи в папку `fraud-detection/`.

## Постановка и метрики

Из-за сильного дисбаланса accuracy бесполезна: модель, которая всегда отвечает «не мошенничество», получает ~99,8%. Модели сравнивались по **Average Precision (PR-AUC)**, она не зависит от порога и чувствительна к редкому классу. Для итогового решения использованы precision, recall и суммарные потери от ошибок.

Валидация: данные разделены на train/test (80/20, стратификация), на train использовалась `StratifiedKFold` (5 фолдов). Все преобразования выполняются внутри `Pipeline`, чтобы не было утечки данных. Тест использован один раз, в самом конце. Признак `Time` не используется: абсолютное время не переносится на новые данные.

## Сравнение моделей (кросс-валидация на train)

| Модель                                                        | Average Precision (mean ± std)        |
| ------------------------------------------------------------- | ------------------------------------- |
| Dummy (baseline)                                              | 0,002 ± 0,000                         |
| Логистическая регрессия                                       | 0,761 ± 0,041                         |
| Логистическая регрессия, `class_weight="balanced"`            | 0,757 ± 0,052                         |
| Random Forest                                                 | 0,828 ± 0,032                         |
| LightGBM, `learning_rate=0.01`, 100 деревьев                  | 0,826 ± 0,017                         |
| LightGBM, `learning_rate=0.01`, 1000 деревьев, `reg_lambda=1` | 0,856 ± 0,021                         |
| LightGBM, итоговая конфигурация                               | TODO: AP по CV (запустить `evaluate`) |

Наблюдения:

- `class_weight="balanced"` почти не меняет AP, он лишь сдвигает вероятности и тем самым перемещает точку на PR-кривой (меняются precision и recall при пороге 0,5).
- LightGBM с параметрами по умолчанию на редком классе давал AP ~0,54. Проблему решило снижение `learning_rate` и увеличение числа деревьев, а не ресемплинг (SMOTE).
- Разница между Random Forest и LightGBM с 1000 деревьями близка к шуму кросс-валидации (~0,02).

## Выбор порога

Порог 0,5 при таком дисбалансе не оптимален. Порог подбирался по out-of-fold вероятностям (`cross_val_predict`) как минимум суммарных потерь `FN · 500 + FP · 2`.

Отношение стоимостей условное (пропуск мошенничества дороже ложной тревоги в 250 раз). Проверка на отношениях от 10:1 до 200:1 показала, что число пропущенных транзакций почти не меняется, а меняется в основном число ложных тревог. Выбранный порог: **≈ 0,0012**.

## Ограничения

- Около 11% мошеннических транзакций модель не ловит ни при каком разумном пороге: их оценки неотличимы от нормальных операций (например, у пропущенной транзакции `score` ≈ 0,000001). Это ограничение модели и признаков, а не порога.
- Отношение стоимостей ошибок задано условно. В реальной задаче его определяет бизнес.
- Вероятности LightGBM не откалиброваны, поэтому API возвращает `score`, а не «вероятность мошенничества».
- Оптимальный порог лежит у нижнего края сетки поиска, и число ложных тревог в этой области чувствительно к сдвигу вероятностей.
- Тест использован один раз, после него конфигурация не менялась. При ~100 мошеннических примерах в тесте метрики имеют заметный разброс (доверительный интервал recall примерно 0,81-0,94).
- Не проверено, помогут ли признак `Time` или признаки на основе `Amount`.

## Запуск

```bash
cd fraud-detection
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Mac/Linux
pip install -r requirements.txt
```

1. Положи `creditcard.csv` в папку `fraud-detection/`.
2. Обучение и сохранение модели (создаёт `models/model.joblib` и `models/config.json`): `python src.py`
3. Запуск API: `uvicorn app:app --reload`
4. Интерактивная документация: http://127.0.0.1:8000/docs

## API

`GET /health` возвращает `{"status": "ok"}`.

`POST /predict` принимает признаки транзакции по названиям (порядок не важен):

```json
{
  "features": {
    "V1": -0.67,
    "V2": 1.41,
    "...": 0.0,
    "V28": 0.29,
    "Amount": 23.0
  }
}
```

Ответ:

```json
{ "score": 9.2e-7, "is_fraud": false, "applied_threshold": 0.00123 }
```

Если не хватает признаков или есть лишние (например, `Time`), сервис возвращает 422 со списками `missing_features` и `unexpected_features`.
