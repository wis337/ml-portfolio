# Titanic: предсказание выживаемости

Бинарная классификация с `Pipeline` и `ColumnTransformer`: препроцессинг без утечки данных, сравнение моделей по кросс-валидации.

## Задача
Предсказать, выжил ли пассажир (`survived`). Метрики: accuracy, precision/recall, ROC-AUC.

## Данные
- 891 строка, датасет `seaborn.load_dataset("titanic")`.
- Классы: 61.6% погибли, 38.4% выжили. Наивный прогноз «все погибли» даёт accuracy 0.616.
- Пропуски: `age` (177), `deck` (688, колонку не используем), `embarked` (2).
- Дублирующие колонки (`class`, `embark_town`, `who`, `adult_male`) и `alive` (прямая утечка цели) убраны.
- По EDA: пол и класс сильно влияют на выживаемость; женщины 3 класса выживали чаще мужчин 1 класса.

## Подход
- Числовые признаки: `SimpleImputer(median)`; категориальные (`sex`, `embarked`): `SimpleImputer(most_frequent)` + `OneHotEncoder`.
- Признаки: `family_size`, `fare_per_person`, `is_child` (считается после заполнения возраста, внутри Pipeline).
- Всё внутри `Pipeline`, поэтому медианы и категории обучаются только на train (в каждом фолде отдельно).
- Split 80/20 со `stratify=y`, затем 5-fold кросс-валидация всех моделей.

## Результаты

| Модель | Train acc | Test acc | CV acc | CV ROC-AUC |
|---|---|---|---|---|
| LogisticRegression | 0.806 | 0.799 | 0.791 ± 0.018 | 0.851 ± 0.017 |
| RandomForest (по умолчанию) | 0.983 | 0.821 | 0.802 ± 0.020 | 0.857 ± 0.038 |
| RandomForest (`max_depth`=5, `min_samples_leaf`=5) | 0.850 | 0.804 | **0.823** ± 0.019 | **0.869** ± 0.027 |
| HistGradientBoosting (по умолчанию) | 0.961 | 0.804 | 0.816 ± 0.030 | 0.861 ± 0.034 |
| HistGradientBoosting (ограниченный) | 0.879 | 0.782 | 0.820 ± 0.019 | 0.864 ± 0.035 |

Подробные метрики baseline (LogReg, test): ROC-AUC ≈ 0.84, recall класса «выжил» 0.67, precision 0.79.

## Выводы
- Все модели лежат в одной полосе (CV accuracy 0.79-0.82, std 0.02-0.03), различия в пределах шума. Оценка по одному test-split вводила в заблуждение: по нему лучшим выглядел дефолтный лес, по CV лучший ограниченный.
- Дефолтные лес и бустинг сильно переобучены (train 0.96-0.98), ограничение глубины сокращает разрыв.
- Новые признаки (`family_size`, `fare_per_person`, `is_child`) качество не улучшили: их информация уже есть в исходных колонках. Это тоже результат.
- Потолок на этих данных около 0.82 accuracy и 0.87 AUC. Следующий шаг: признаки из имени пассажира (обращение Mr/Mrs/Miss/Master), которых нет в версии датасета из seaborn, но есть в оригинале с Kaggle.
